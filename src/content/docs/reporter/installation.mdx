Nijam ships a reporter for each supported framework — `@nijam/pw-reporter` (Playwright), `pytest-nijam`
(pytest), and `@nijam/vitest-reporter` (Vitest). Each is open source, **fail-soft** (it never breaks your
test run), and uploads to the same ingestion API.

<Aside type="note">
All three capture run history, per-test status, the error log, the failing line, duration, and retries
(for flakiness), plus optional test-source upload. **Traces, screenshots, and video are Playwright-only** —
pytest and Vitest report the error log and failing line, with no traces.
</Aside>

## Install & configure

Pick your framework below.

<Tabs syncKey="framework">
<TabItem label="Playwright">

[`@nijam/pw-reporter`](https://www.npmjs.com/package/@nijam/pw-reporter) is zero-dependency and declares
`@playwright/test` (>= 1.40) as a **peer dependency**, so it uses the Playwright you already have.

<Tabs syncKey="pkg">
<TabItem label="npm">

```sh
npm install --save-dev @nijam/pw-reporter
```

</TabItem>
<TabItem label="pnpm">

```sh
pnpm add -D @nijam/pw-reporter
```

</TabItem>
<TabItem label="yarn">

```sh
yarn add -D @nijam/pw-reporter
```

</TabItem>
</Tabs>

Playwright's `reporter` field takes a list, so add Nijam alongside any reporters you already use:

```ts title="playwright.config.ts" {6-9}
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['list'], // keep your existing reporters
    ['@nijam/pw-reporter', {
      apiKey: process.env.NIJAM_API_KEY,
      projectId: '<your-project-uuid>',
    }],
  ],
});
```

</TabItem>
<TabItem label="pytest">

[`pytest-nijam`](https://pypi.org/project/pytest-nijam/) is a pytest **plugin** — installing it is enough
for pytest to auto-load it; there's **no code to add**.

```sh
pip install pytest-nijam
```

Configure it in `pytest.ini` (or `[tool.pytest.ini_options]` in `pyproject.toml`) and set the API key as
an environment variable:

```ini title="pytest.ini"
[pytest]
nijam_project_id = <your-project-uuid>
```

```sh
export NIJAM_API_KEY=...
```

See the [pytest reporter docs](https://docs.nijam.dev/reporter/pytest/) for the full ini-option list.

</TabItem>
<TabItem label="Vitest">

[`@nijam/vitest-reporter`](https://www.npmjs.com/package/@nijam/vitest-reporter) plugs into Vitest's
`reporters` list.

<Tabs syncKey="pkg">
<TabItem label="npm">

```sh
npm install --save-dev @nijam/vitest-reporter
```

</TabItem>
<TabItem label="pnpm">

```sh
pnpm add -D @nijam/vitest-reporter
```

</TabItem>
<TabItem label="yarn">

```sh
yarn add -D @nijam/vitest-reporter
```

</TabItem>
</Tabs>

Add it to `test.reporters` and enable `includeTaskLocation` so Nijam can capture the failing line:

```ts title="vitest.config.ts" {7,10-13}
import { defineConfig } from 'vitest/config';
import NijamReporter from '@nijam/vitest-reporter';

export default defineConfig({
  test: {
    includeTaskLocation: true, // required to capture the failing line
    reporters: [
      'default', // keep your existing reporters
      new NijamReporter({
        apiKey: process.env.NIJAM_API_KEY,
        projectId: '<your-project-uuid>',
      }),
    ],
  },
});
```

</TabItem>
</Tabs>

The two required options are `apiKey` and `projectId` — see [Configuration](/reporter/configuration/) for
the full list and where to find them.

<Aside type="tip">
Put `NIJAM_API_KEY` in your CI secrets and reference it via the environment. Don't hard-code the key in the
config file.
</Aside>

## Verify

Run your suite. If Nijam is reachable and the credentials are valid, the run shows up in your project in
the [dashboard](https://www.nijam.dev). If something's off (bad key, wrong project, network), the reporter
prints a `[nijam]` warning and your tests still pass/fail exactly as before.
