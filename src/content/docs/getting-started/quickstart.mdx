This guide takes you from a fresh account to seeing your first run in the dashboard.

<Steps>

1. **Create an account.**

   Sign up at [nijam.dev](https://www.nijam.dev) — **continue with Google or GitHub**, or use your email
   and a password. You'll land on your organizations screen.

   <Aside type="tip">
     These all sign you into the **same account** when they share an email — sign up with a password and
     later "continue with Google", or vice versa, and you land in the same place. (To add a password to a
     Google/GitHub-only account, use **Forgot password** to set one.)
   </Aside>

2. **Create an organization.**

   An [organization](/concepts/organizations/) holds your projects, runs, and team. Create one (or accept
   an invite to an existing one). Every new account can create up to **2 organizations**.

3. **Create a project and copy its ID.**

   Inside your org, create a [project](/concepts/projects/) — one per Playwright suite/repo. Copy its
   **Project ID** (a UUID); the reporter needs it.

4. **Generate an API key.**

   In the project's settings, generate an **API key**. Treat it like a password — store it as a CI secret,
   not in your repo.

   <Aside type="caution">
   The API key authorizes uploads to your project. Keep it in CI secrets (e.g. `NIJAM_API_KEY`) — never
   commit it.
   </Aside>

   <Aside type="note">
   This is an **ingestion key** (`nij_sk_…`) — it can only upload, never read. To let AI agents query
   your runs, create a separate read-only key and follow the [MCP server](/integrations/mcp/) guide.
   </Aside>

5. **Install the reporter.**

   ```sh
   npm install --save-dev @nijam/pw-reporter
   ```

   Using pnpm or yarn? See [Installation](/reporter/installation/) for those commands.

6. **Add it to `playwright.config.ts`.**

   ```ts title="playwright.config.ts"
   import { defineConfig } from '@playwright/test';

   export default defineConfig({
     reporter: [
       ['@nijam/pw-reporter', {
         apiKey: process.env.NIJAM_API_KEY,
         projectId: '<your-project-uuid>',
       }],
     ],
   });
   ```

   Keep your existing reporters too — Playwright accepts a list, so Nijam runs alongside `list`, `html`,
   etc.

7. **Run your tests.**

   ```sh
   NIJAM_API_KEY=... npx playwright test
   ```

   On a real CI run, commit/branch/PR/author are [detected automatically](/reporter/ci-integration/) — no
   extra config.

   <Aside type="tip">
     The reporter prints a link to the run straight to your terminal (and your CI logs) — once when it
     **starts** and again when it **finishes**, so it's there to click without scrolling back:

     ```text
     [nijam] run started — view it at https://www.nijam.dev/...
     ...
     [nijam] run finalized (12/14 passed) — view it at https://www.nijam.dev/...
     ```

     Click it to jump to the run in the dashboard — no need to go hunting for it. (Set `silent: true` to
     suppress all `[nijam]` output.)
   </Aside>

8. **Open the dashboard.**

   Back in [nijam.dev](https://www.nijam.dev), open your project. Your run is there, with its results,
   any failure traces, and the start of your test history.

</Steps>
